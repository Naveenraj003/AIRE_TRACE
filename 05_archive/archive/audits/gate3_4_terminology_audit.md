# Terminology Audit Report

| Term | Definition | Files | Conflicts | Recommended canonical definition |
|---|---|---|---|---|
| **task** | A specific benchmark task definition or environment goal (e.g., 89 unique tasks in TerminalBench). | `gate1_report.md`, `gate2_1_report.md`, `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_4_protocol_compliance.md` | Sometimes conflated with "episode". Protocol explicitly separates task definition from execution run to ensure task-group disjoint splitting. | A unique environment goal or benchmark task definition, distinct from an individual execution run. |
| **episode** | A single execution run of an agent attempting a task. The fundamental statistical unit for evaluation. | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate1_report.md`, `gate3_1_report.md`, `gate3_4_protocol_compliance.md` | Used interchangeably with "run" and occasionally "trajectory". | A single full execution run of an agent attempting a task, forming the fundamental statistical unit for evaluation and splitting. |
| **trajectory** | The complete sequence of events (actions, observations, states) recorded during a single episode. | `gate2_1_report.md`, `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `RESEARCH_LOG.md` | Often used as a synonym for "episode" in dataset naming (e.g., `historical_trajectories`), though technically it refers to the data sequence itself. | The full sequence of recorded events (steps) comprising an episode. |
| **prefix** | A truncated trajectory containing steps from the beginning of an episode up to a specific step $t$ (checkpoint). | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_1_report.md`, `gate3_4_protocol_compliance.md` | None found. Consistently used to denote partial execution traces. | A sequence of events from step 1 up to a checkpoint step $t$, used as input for models. |
| **run** | A single execution run. | `gate1_report.md`, `gate3_1_report.md` | Used interchangeably with "episode", which can cause ambiguity when referring to experiment runs vs. agent execution runs. | Synonymous with "episode". "Episode" should be the exclusively preferred term to avoid confusion with experiment runs. |
| **checkpoint** | A specific step index $t$ at which a prefix is extracted and evaluated. | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_4_protocol_compliance.md` | None found. | The specific step index $t$ at which a prefix is extracted for evaluation or training. |
| **failure** | The negative outcome of an episode. | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_1_report.md`, `RESEARCH_LOG.md` | Dataset-native failure (e.g., reward=0) vs. canonical `eventual_failure`. Must be mapped canonically per Rule 10. | The canonical `eventual_failure` outcome mapped from the benchmark's native success/failure determination. |
| **warning** | An alert triggered by a monitor on a prefix when the predicted probability exceeds a calibrated threshold. | `gate3_1_report.md`, `gate3_2_reconciliation.md`, `AIRE-Trace_Frozen_Protocol_and_Plan.md` | Used generically, but formally means $y_{prob} \ge \tau^*$. | An alert emitted by a monitor at a specific checkpoint predicting eventual failure. |
| **early warning** | A valid prospective warning issued at or before the failure onset step ($t \le t_{onset}$). | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_1_report.md` | Heavily dependent on the definition of "onset". Evaluated under Mode A. | A valid prospective warning issued at or before the failure onset step ($t \le t_{onset}$). |
| **onset** | The step at which failure behavior first manifests or becomes irreversible (e.g., `min(incorrect_step_ids)`). | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate1_5_report.md`, `RESEARCH_LOG.md`, `gate3_1_report.md` | Variously referred to as `failure_onset_step`, `t_onset`, or `first_incorrect_step`. Undefined/unannotated for TerminalBench. | The specific step $t_{onset}$ where failure behavior first manifests; determines eligibility for prospective warning evaluation. |
| **success** | The positive outcome of an episode. | `AIRE-Trace_Frozen_Protocol_and_Plan.md`, `gate3_1_report.md`, `RESEARCH_LOG.md` | Dataset-native success vs. canonical `eventual_success`. | The canonical `eventual_success` outcome mapped from the benchmark's native success criteria. |
